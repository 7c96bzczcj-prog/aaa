### 重要更正：P2 的数字与规范不符，已按真实数据修改

规范 P2 要求「大数字 `~1%`」+ 数据源 GSE154826。**这两者对不上，如按规范原样做会在答辩时被问穿。**

从 `results/cell_counts_by_group.csv` 实测（single-mode 文库，28 例配对病人，
共 243,917 个细胞）：

| 谱系 | 肿瘤内占比 | 癌旁占比 |
|---|---|---|
| 髓系 | 28.7% | 39.0% |
| B | 20.0% | 15.3% |
| 未分配 | 18.8% | 13.9% |
| CD4T | 17.8% | 14.3% |
| CD8T | 10.7% | 10.1% |
| **NK** | **4.0%** | **7.4%** |

原因：**GSE154826 是 CD45⁺ 富集数据**，所以 4.0% 是「占免疫细胞」的比例。
规范里的 ~1% 是**未分选组织**的数字（GSE178341 Pelka，NK 约占全部细胞 1.1%），
属于另一个数据集、另一个分母。

**处理**：主数字用真实的 **4.0%**，并在其下以小字注明「未分选组织中约 1%
（GSE178341）」。两个数都真实、都可溯源，论点（NK 极少）不受影响，反而更强
——因为 4.0% 是**已经富集之后**的数字。

「未分配」一条如实保留，未从分母中剔除，剔除会改变 NK 的百分比。

## 五、交付前检查：规范 §4 的目检步骤无法执行，已用几何审计替代

规范要求 `soffice --convert-to pdf` → `pdftoppm` → 逐张看图。

**soffice 在本环境已损坏** —— 它连一个纯 `.txt` 文件都无法转换
（`Error: source file could not be loaded`），并非 PPTX 的问题；`pdftoppm` 未安装。
PPTX 本身结构有效：12 页、4 个原生图表、全部 XML 通过解析。

**替代方案**：`scripts/audit_ppt.py` 直接从 PPTX XML 读取每个图元的坐标与尺寸，
检查规范点名的四类问题——文字溢出、元素重叠、来源标签与正文碰撞、页边距不足——
外加每页正文中文字数预算。

**首次审计报出 32 个问题，全部已修**：

| 问题 | 修法 |
|---|---|
| 标题 y=0.45，越过 0.6 边距（10 页） | 下移至 y=0.62 |
| 来源标签底部越界（7 页） | 上移至 y=6.55 |
| P2 `4.0%` 在 60pt 下溢出（fill=1.10） | 框高 1.10″ → 1.42″ |
| P9 右侧 Aim 框超出右边距（13.10″ > 12.73″） | 框宽与间距重排 |
| P5 正文中文超预算 | 红线二的说明移入讲稿，页面只留标记 |
| 图表坐标轴线用了 pptxgenjs 默认 `888888` | 显式指定为规范灰 `D9D9D9` |
| P10 左侧小色条（疑似「侧边竖条」） | 删除 |

**当前状态：几何审计零问题。**

**这个替代方案的局限，如实说明**：它是几何检查，不是视觉检查。
它**看不到**颜色的实际观感、字体替换效果、以及图表的最终渲染。
建议在你自己的机器上用 PowerPoint 打开后再翻一遍，重点看：
中文字体是否按 `Microsoft YaHei` 正常显示、4 个原生图表的实际外观、
以及 P7 双时间轴的圆点与文字对位。
